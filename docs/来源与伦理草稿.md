## 0. 产品自称、禁止自称

首页、页脚、提交文案、两分钟口播，四处口径必须一致。

| 我们自称 | 我们不自称 |
|---|---|
| 国标手指字母**陪练** | 手语翻译器、手语输入法 |
| 对着镜头练、错了指出哪根手指 | 学习完成证书、已经学会手语 |
| 识别在本机完成，默认不上传视频 | 云端高精度识别、医疗器械 |
| 内容对齐公开国标 | 本队发明的手语、ASL 中文版 |

观念层红线（写进提交文案也不许踩）：

- 不声称替代手语老师，不声称治疗沟通障碍。
- 不做听力筛查、不做医疗诊断。
- 不把用户视频默认上传。
- 不发明「我们队的手语」。争议手型只写在字母包 `notes`，不写进判定口号。

## 2. MediaPipe Hand Landmarker

**是什么。** Google AI Edge / MediaPipe Tasks Vision 的手部关键点方案：一张图或一帧视频 → 最多若干只手的 21 个点（手腕到指尖）。本项目在浏览器里用 `HandLandmarker`，`VIDEO` 模式，模型文件放进仓库，现场不靠外网。

**用在哪。** 只在感知层。输出是中性几何：点、左右手、置信度、是否出框。这一层禁止写死「这是字母 M」。字母判定在理解层，用规则卡。

**许可。** Apache License 2.0。

**引用。**

- 项目与代码：<https://github.com/google-ai-edge/mediapipe>
- 方案说明：<https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker>
- 本仓库：`practice/vendor/vision_bundle.mjs`、`practice/vendor/wasm/`、`practice/models/hand_landmarker.task`

**本队做了什么、没做什么。**

- 做了：本机加载、GPU 失败回退 CPU、画出骨架、镜像开关、「请只伸一只手」。
- 没做：没有改训练权重，没有自训检测网，没有把用户视频送到 Google 或其他服务器做推理。

**伦理上要说清的。** 摄像头画面在本机进模型。页脚和演示口播使用同一句：**识别在本机进行，视频不上传。** 不要把 MediaPipe 说成「我们的识别模型」。

**【待补】** 提交前核对 `vision_bundle.mjs` 对应的 `@mediapipe/tasks-vision` 版本号，写入本表，不要估。

## 3. GF 0021—2019《汉语手指字母方案》

**是什么。** 国家语言文字规范，规定汉语手指字母的手型。国家通用手语里，人名、地名、专有名词常要落到这一层。本产品第一期只陪练手指字母，不覆盖常用词表里的词句。

**用在哪。** 内容层唯一手型依据。字母 ID 一律 `GF0021.*`（如 `GF0021.U`）。规则 JSON 是国标外形的几何近似，**不是新发明的手语**。J、Z 在规范里带轨迹，第一期只核静态手型，文案必须写明。

**主路径为什么是 8 个。** `A B U V L Y I W`：能看懂、能分开、能在两分钟里演示。U/V 是易混对（并拢 vs 分开）。其余 24 个留在图鉴；M/N/S、E/ê 若规则分不开，标「易混」，不许假装能分。

**引用。**

- 规范名称：GF 0021—2019《汉语手指字母方案》
- 发布：中华人民共和国教育部、国家语言文字工作委员会
- 字母包字段：`practice/content/letters.json` → `"standard": "GF 0021-2019"`
- SignPinyin 作者提供的规范文本链接（提交前须在教育部官网核对现行件）：<http://www.moe.gov.cn/jyb_sjzl/ziliao/A19/201404/W020191101556565933988.pdf>

**本队不许做的。**

- 不用 ASL 手指拼写当国标内容，不用 Kaggle ASL 图集冒充国标数据。
- 不把地区变体、课堂习惯手型写进判定口号；有争议只进 `notes`。
- 不声称「覆盖国家通用手语」——常用词表是另一套规范，第一期不做。

**【待补】** 提交包放规范全称、发布机关、队员核对日期。不要在演示里改手型「为了好看」。

## 4. SignPinyin

**是什么。** 汉语手指字母字体，用线条画手形，覆盖 GF 0021 字母。作者在其说明书里写明：**这不是手语字体**；使用前须分清手指字母和手语。

**用在哪。** 初版练习页用 Regular 字形当示范。规划已裁定：正式主示范改为 Blender 标准手，SignPinyin **降为角标**，避免初学者从字形反推手指。

**许可。** SIL Open Font License 1.1。保留字体名 SignPinyin / SignPinYin。可以嵌入软件；改字体须遵守 OFL（衍生字体不得改用保留名，也不得改换许可证）。

**引用。**

- 仓库：<https://github.com/ErSanSan233/SignPinyin>
- 版权声明（字体内 LICENSE）：Copyright (c) 2025, ErSanSan233 & Zhang 3-er，Reserved Font Name SignPinyin / SignPinYin
- 本仓库字体文件：`practice/fonts/SignPinyin-Regular-0.6.ttf`（以及上游 `SignPinyin/fonts/`）
- 作者声明的内容依据：GF0021—2019《汉语手指字母方案》

**必须告诉评委的。**

- 字体 ≠ 识别模型。没有「用字体做分类」。
- 字体 ≠ 手。预选页左边主图应是 3D 标准手；字体只帮助辨认字母是哪一个。
- 大写字母在该字体里有艺术手形，**不符合方案的不要当教学内容**。本队 JSON 与演示以国标小写手型为准。

## 5. fingerpose（工程思路，不是内容）

**是什么。** 在 MediaPipe 手部点上估计每指弯曲与朝向，再和手势描述比对。示例手势是 Victory、Thumbs Up，与国标无关。

**用在哪。** 理解层**思路**：弯曲、朝向、张角 → 规则卡。本队规则写在 `letters.json`，hint 落到具体手指。

**许可。** MIT（andypotato/fingerpose）。

**引用。** <https://github.com/andypotato/fingerpose>

**必须说清的。** 这是工程参考，不是国标词典。禁止把它的内置手势直接映射成 GF 0021 字母。仓库里的 `fingerpose/` 是上游 clone，gitignore，不计入本队作品。

## 6. Blender 与标准手

**定位。** Blender 是内容工厂，不是运行时。它产出可以引用、可以复现的国标手，**不进入**摄像头识别循环。预选**不做**用户骨骼驱动的实时虚拟人。

**计划产出（PNG 还没进仓库，写成待补，不要用完成时）。**

文件名约定（已写入 `practice/content/demos/README.md`，**不是已经出图**）：

```
{字母ID}_front.png
```

例子：`GF0021.U_front.png`、`GF0021.V_front.png`。不能叫 `fist1`、`hand_u`。

| 产出 | 用途 | 状态 |
|---|---|---|
| `blender/hand_gf0021.blend` | 五指独立、掌心可读的绑定手 | **待补** |
| 主路径 8 个姿态的正面 PNG | 练习页左栏主图 | **待补**（目录里还没有这些文件） |
| `blender -b` 渲染脚本 | 可复现出 PNG | **待补** |
| `practice/content/demos/` | 页内示范图 | 目前只有 README，约定了文件名 |

**许可怎么写。**

- Blender 软件本身是 GNU GPL。用 Blender 做出的 **PNG / 自己绑的骨骼** 不自动变成 GPL；本队原创姿态按本队作品声明。
- 若绑定手来自第三方（BlenderKit、付费/CC 手模）：**必须在本表加一行**，写作者、许可、有没有改拓扑。没有这一行，不许上预选包。
- 禁止：用 ASL 手形资源充 GF 0021；把渲染图说成识别精度；把 glTF 跟手当成感知层。

**页上要出现的那句（来源页和练习页同步）。**

> 3D 示范按 GF 0021—2019 摆，是给人看的标准手，不是识别模型。

## 7. 自录关键点

**为什么要录。** 国标字母没有可下载的开源识别器。第一期不训检测网，但理解层需要夹具：同样的 21 点，规则该说「并拢」还是「分开」，不能每次打开摄像头才知道。U/V 实验失败时，要分得清是 MediaPipe 抖，还是规则写错。

**录什么。** 浏览器里的 `HandFrame`（时间、左右手、21 点、置信度、是否出框），**不是默认录视频。** 若某次必须留画面，走单独的采集模式：明示、可关、可删、文件留本机。

**拍摄条件必须写在日志里的字段。**

- 日期、设备、浏览器
- 光照（窗光 / 灯 / 逆光）
- 距离、镜像开或关、左手还是右手
- 目标字母 ID（`GF0021.U` / `GF0021.V` …）
- 人：匿名代号（P1、P2），是否队员
- 同意方式（口头 / 书面），可否进入提交包

**许可与伦理。**

- 只采同意了的人。未成年人须监护人同意；本队若未做，本节写「未采集」，不要补假同意。
- 默认不外传、不上网盘「图个方便」。进入仓库的只能是关键点 JSON 和不可辨认面貌的说明，视频另存本机。
- 本人要求删除：删文件、改日志为「已删」，不要留备份炫耀。
- **不是公开数据集。** 未采集时写「尚无自录」；有了也不报准确率，只报「这两条夹具能分开 / 分不开」。

**【待补】** 第一条夹具的路径、人数、失败案例截图位置。立档日：**尚无自录关键点。**

## 8. 摄像头与隐私

| 规则 | 做法 |
|---|---|
| 主路径无上传 | 练习页识别不把图像或特征发到本队服务器（本队第一期无后端） |
| 权限 | 浏览器 `getUserMedia`；用户拒绝则走无摄像头：只看标准手，不评分 |
| 现场 | 用 localhost 或 HTTPS；演示前断网演练一次 |
| 采集与演示分离 | 采集若发生，另开页，不藏在陪练按钮里 |
| 镜像 | 默认开，可关；提示请伸一只手 |

页脚现用句，来源页保持原句，不要改成更「科技」的说法：

> 感知：MediaPipe Hand Landmarker（本机）· 理解：几何规则，不显示分数 · 内容：公开国标

示范换成标准手之后，页脚补一句「3D 示范不是识别模型」。SignPinyin 若仍作角标，保留「字体仅作角标」。

## 9. 演示与拍摄同意

两分钟路径与页面锁定见过程篇第 10 节：**开摄像头 → 比 U → 看左边标准手 → 听 hint 或「到位」→ 切 V。**

演示伦理：

- 评委或志愿者上手前，说明：画面本机处理、不录像除非另行同意。
- 录屏若含人脸：提交前裁到手，或取得同意。
- 口播只读页面上有的字（「打开摄像头」「到位」、具体 hint）。没有分数就不要报分数。
- 分不开 U/V 时，承认失败，不改口成翻译产品。

## 10. 我们不声称的事项（可直接贴进提交说明书的「范围」）

1. 不会让人「学会手语」。手指字母是拼写层，不是国家通用手语的词句。
2. 没有翻译整句、没有 500 词识别、没有方言全覆盖。
3. 没有自训检测网，没有本队准确率榜。
4. 没有医疗、康复、听力诊断功能。
5. 没有把 ASL 或字体或 3D 渲染当成识别依据。
6. 没有实时虚拟人跟手（预选明确不做）。
7. 尚未完成的标准手、夹具、真人试，不写成已经完成。

# 前端产品化迭代

## 目标与方向

面向可落地的教育陪练应用，采用米白宣纸底、墨绿操作色与少量朱砂色标记；首页先介绍和引导，不直接呈现摄像头任务。暂以「指间」作为产品展示名。保持纯静态架构，不新增框架或依赖，不调整判定阈值或提升 practiceStatus。

本轮选用独立首页 + learn.html 学习页，而非单页路由或引入框架：首页不加载 app.js / MediaPipe；既有摄像头生命周期和判定逻辑仍在学习页运行，减少重构风险。

## 第一轮：入口与视觉基础（本地已实现，整体验收未完成）

- learn.html 承接现有练习功能；摄像头只由按钮显式启动。
- 首页、学习页、来源页采用统一导航、页脚、配色、排版、焦点样式及响应式规则。新增首屏轻入场和按钮反馈，尊重 prefers-reduced-motion。
- 学习页去除标准编号标题，技术导出工具折叠到高级问题排查；合法来源信息保留在次级页面。
- pose-goldens.test.js 已加入 AGENTS.md、README.md 的必跑清单及 .github/workflows/test.yml；尚未推送，远端 Actions 未执行。

## 第七轮：手机仿真触摸点击排查（已定性为工具伪影）

- 背景：此前在 390×844 responsive 仿真下曾观察到点击异常。两轮专项排查。
- 代码审查：`practice/app.js` 零 touch/pointer 监听、零 preventDefault（仅一个 visibilitychange）；`styles.css` 无 touch-action 限制，pointer-events 仅用于关闭摄像头时禁用视频覆盖层；按钮监听是普通 click（app.js:356），`selectLetter`（app.js:324）无任何门槛。
- 对照实验（responsive 仿真，390×844）：
  - 合成 `page.element.click` 与坐标 `click_if_interactive`（工具确认命中目标并发出 click）对 W、L、自测按钮均无效；
  - 同一按钮用 `press_key Enter` 立即生效（6–7ms 内标题/模式即切换，先后验证 L 与自测模式）；
  - 合成点击在桌面模式下始终有效，仅在 mobile/touch 仿真下失效。
- **结论：这是浏览器自动化工具在移动仿真下的合成点击派发伪影，不是前端 bug**。同一套按钮键盘操作完全正常，应用代码无可修之处。
- 仍建议真机抽查一次连点字母按钮作为最终确认（仿真无法 100% 替代真机触摸），但现有证据已排除前端责任。后续自动化验收在仿真下用键盘/回车驱动，不再用合成点击。
- 手机竖屏布局截图确认正常（单列、按钮尺寸足够、分组可键盘展开）。
